# widget_bank
Учебный проект на Python 3.12 для отработки базовых навыков разработки: работа с данными, типизация, тестирование,
логирование и управление зависимостями через Poetry.

> ⚠️ **Важно:** Все сгенерированные номера карт — **тестовые**, не являются валидными платёжными инструментами


## Цель проекта: 
освоить элементарные команды для работы с GIT


## Описание:

Главный файл для запуска: *src/main.py*

В нём реализован модуль main, который организует интерактивный диалог с пользователем:
- Выбор источника данных. 
- Фильтрация по статусу операции. 
- Сортировка по дате. 
- Поиск по ключевому слову. 
- Форматированный вывод. 

Для переводов дополнительно выводится направление: from → to с маскировкой обоих номеров.
## Инструкция для запуска из консоли

Скопируйте и в консоли выполните команду : 

```bash
poetry run python -m src.main
```

## Тесты 
Добавлены unit-тесты для всех функций проекта.
Тестирование выполняется с помощью фреймворка <span style="font-size: 120%; color: green; font-family: monospace;">pytest</span>
Дополнительно установлена библиотека **pytest-cov** для оценки процента тестирования

Запуск тестов выполняется командой:
```bash
# Запуск тестов с отчётом о покрытии
pytest --cov

# Запуск только определённых тестов (пример)
pytest tests/test_main.py

# Запуск тестов с генерацией html-отчёта
pytest --cov=src --cov-report=html
```

## Входные данные содержаться в файле *data/transactions.json*
Файл подключается как при работе приложения, так и при тестирования. Иммитирует данные о текущих транзакциях
- **Загрузка транзакций** из `data/transactions.json` с безопасной обработкой отсутствия файла и ошибок формата JSON.
- **Фильтрация по валюте** (`filter_by_currency`) через генератор — экономит память при работе с большими наборами данных.
- **Извлечение описаний операций** (`transaction_descriptions`) — ленивая выдача строк без создания промежуточных списков.
- **Генерация последовательных номеров карт** (`card_number_generator`) в формате `XXXX XXXX XXXX XXXX` для использования в тестах (например, для `get_mask_card_number`).
- **Устойчивость к битым данным**: пропуски транзакций с отсутствующими полями вместо падения скрипта.

 🛠 Декоратор логирования `@log`

Декоратор `log` из модуля `src.decorators` предназначен для быстрого протоколирования вызовов функций: фиксирует входные аргументы, результат или ошибку, длительность выполнения и сохраняет запись в файл или выводит в консоль.

> ⚠️ **Важно для проекта widget_bank**: декоратор по умолчанию логирует `args` и `kwargs`. Если туда попадают чувствительные данные (номера карт, токены и т.п.), они окажутся в лог-файле в открытом виде.

## Другие входные данные содержаться в файлах *data/transactions.csv и transactions.xlsx*
Имеется модуль [dataframe_to_json.py](src/utils/dataframe_to_json.py) для работы с DataFrame, который преобразует табличные данные
в json-данные нужной структуры, согласно файлу [transactions.json](data/transactions.json)


## 📁 Где хранятся логи

Логи сохраняются относительно **корня проекта** (не от папки запуска скрипта). Декоратор автоматически определяет корень по расположению файла `src/decorators.py`:


- `<корень_проекта>/tmp/logs.txt`

Папка `tmp` создаётся автоматически при первом использовании декоратора.

## Настройка окружения и линтинг
Для поддержания качества кода в проекте используются:

mypy — статическая проверка типов;
flake8 — проверка стиля и простых ошибок;
isort и black — автоматическое форматирование импортов и кода.
Запуск проверок:
```bash
poetry run isort .
```
```bash
poetry run black .
```
```bash
poetry run flake8 .
```
```bash
poetry run mypy src/
```
